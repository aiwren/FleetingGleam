# 整体优化审查（2026-10-26）

作者在单击进大图之后问"整体再看一下 APP 还有没有什么可以优化的地方"。三路只读审查（Android 界面、Rust 核心、macOS 前端）并行完成，重点条目逐条抽查过代码。每条：位置、问题、改法、收益。做完一条就在这里打勾。

真机实测（小米 25128PNA1C，当前包）：冷启动 114 ms；空闲 PSS 105 MB；安装包 84 MB（解压 225 MB，其中 QNN 库 200 MB：`libQnnHtpPrepare.so` 84 MB 只有第一次编译 NPU 图用，六代 HTP 的 Skel 各 9–17 MB、一台手机只用一份）。

## 优先做（跨端、真 bug 或体验硬伤）

### Android

1. [x] **SAF 权限失效会把镜像整个清空**（`core/Media.kt:126-160`）。`TreeDocumentFile.listFiles()` 在权限被收回、网盘离线时吞异常返回空数组 → `keep` 为空 → `walkBottomUp().delete()` 把镜像里每一张照片删掉。改法：同步前核对 `persistedUriPermissions`；`found` 为空而镜像非空时当作列举失败、跳过删除；界面给"重新授权"。收益高（避免静默丢数据）。
2. [ ] **大图查看器 4096² 解码 × 三页**（`ui/project/Viewer.kt:420/220/333`）。一张 64 MB，三页近 190 MB，还把 480px 墙缩略图挤出 Coil 缓存，退回墙上要重解。改法：解码边长 = 屏幕长边 × 2 封顶 4096；该请求不进内存缓存；非当前页置空 large/sharp。收益高。
3. [ ] **大图缩放每帧重组、手势检测器每帧重启**（`Viewer.kt:205/334/355/442`）。`pointerInput(scale)` 以 Float 为 key；组合层读 `Animatable.value`。改法：key 改布尔；detail 触发改 `snapshotFlow` + debounce；小地图条件用 `derivedStateOf`。收益高（缩放掉帧主因）。
4. [ ] **照片墙捏合插值用过期的 items / width / layout**（`ui/project/Wall.kt:254` `pointerInput(Unit)`）。换筛选、切网格↔瀑布、旋转后再捏，目标布局按旧数据算。改法：`pointerInput(items, width, layout)` 或 `rememberUpdatedState`。收益高。
5. [ ] **`CullState.coords` 只增不减**（`Culling.kt:144/157`，写入点 `Culling.kt:385`、`Scanning.kt:109/121`、`Single.kt:158`、`Compare.kt:267`）。持有每个滚过的格子的 LayoutNode；`Session.results/stages/live` 换项目也不清。改法：`DisposableEffect` 里 remove；`Session.enter()` 清三个表。收益中高。
6. [ ] **对比页缩放每帧重组整个 CompareView；人物筛选下每帧重算 groupBy**（`Compare.kt:190/303/317/124`，`Culling.kt:366` 的 `filter` 没 remember）。改法：`view` 只在 `graphicsLayer` 里读；过滤包进 `remember`。收益中高。
7. [ ] **`stopScan()` 阻塞调用落在主线程**（`Session.kt:314` → `callBlocking`；调用方 `ProjectScreen.kt:145`、`AnalysisService.kt:36`、`Scans.kt:29-45` 温度 / 电量回调）。改法：`scope.launch`。收益中（消除一类 ANR）。

### Rust 核心

8. [ ] **Android 分析解码走三段路**（`analyze.rs:361-381`、`apps/android/rust/src/lib.rs:72-92` 没实现 `SystemImages::decode`，`core/Images.kt:43-51`）。每张：Kotlin 解码 → 缩放 → 压 JPEG 写盘 → Rust 再解 JPEG → 删文件。改法：`ImageHelper.decode(path, max) -> RGB 像素`，Rust 端 `RgbImage::from_raw`。收益高（估 20–40 ms/张，少写 flash）。
9. [ ] **Android 上 HEIC / AVIF 的大图预览按 `max = 30000` 整张解码**（`analyze.rs:316`；`Images.kt:46-48` 的 `sampleFor` 变成 1；`Large.kt:36` 还会预取几张）。48 MP HEIC 约 190 MB 位图，极易 OOM，`large/` 很快撑满。改法：非原生格式也用 2560，或 `SystemImages::preview_max()` 按平台给。收益高。
10. [ ] **分析缓存每次整文件重写 + fsync，且在 `cache` 锁内**（`cache.rs:275-288`、`engine.rs:680-689/733-748/1061-1081`）。万张项目每分钟重写几百 MB JSON，期间所有 `with_cache` 排队；转一张照片也全量重写。改法：追加式日志 / 分片；至少序列化移出锁。收益高。
11. [ ] **MediaPipe 眼睛模型被加载两份、人脸流水线每次分析重新加载**（`engine.rs:564/662/783/812`、`facepipe.rs:133-137`）。改法：`Factory` 缓存 `Arc<FacePipeline>`；一次 `scan_project` 只 `start_vision` 一次。收益高。
12. [ ] **分析失败的照片被静默丢弃**（`engine.rs:749` `eprintln!("skip")`，核心共 16 处 `eprintln!`，Android 的 stderr 没人看）。界面上照片就"消失"。改法：统一 `platform::log` + `emit("scan-skip", {path, error})`。收益高（可诊断）。

### macOS

13. [ ] **分析期间整页只能看**（`Culling.tsx:918` `interactive={phase === "done" && …}`，搜索 / 视图 / 整理 / 设置按钮都 disabled）。几千张要跑几十分钟，已判定的既不能选也不能改判。改法：有 `photo` 的格子分析中也可交互，`decide` 对 `live` 生效，只把整理留到结束。收益高。
14. [ ] **分析中每帧重排整面墙**（`Culling.tsx:481-491` `items` 依赖 `tick`，`Wall.tsx:131` 每帧重跑 `place()`）。改法：静态部分（key / ratio）和动态部分（photo / stage）拆开。收益高。
15. [ ] **每个 Tile 开 motion `layout="position"`**（`Tile.tsx:85`），位置本来由绝对定位给出，每帧上百次强制布局读取。改法：去掉 layout 或只在 done 后开。收益高中。
16. [ ] **墙上没有上下键和多选**（`Culling.tsx:580-601`），连拍 20 张只能一张张点。改法：`rowNeighbour`，shift 范围 / ⌘ 追加，`decide` 接受数组。收益高。
17. [ ] **Viewer 快捷键闭包过期（两个真 bug）**（`Viewer.tsx:348-369` 依赖漏 `help`、`active`）：帮助气泡开着按 Esc 直接关查看器；进设置页在输入框敲 p/r/x 仍改判。收益中。

## 第二批（性能中档）

- [ ] Android：分析期间 20 个 StateFlow 全在 `ProjectScreen` 顶层 collect，每个进度事件整页重组；`rememberScanData` 在 Done 阶段也无条件跑（`ProjectScreen.kt:68-105`）。下沉到各自组件。
- [ ] Android：分析中页签 `items = shown.map` 没 remember（`Scanning.kt:115`），每 tick 重排整面墙、预取重启。
- [ ] Android：单张翻页在组合层读 `currentPageOffsetFraction`（`Single.kt:103`），应挪进 `graphicsLayer`。
- [ ] Android：全屏 60dp 模糊背景（`Viewer.kt:200`、`Single.kt:100`、`Scanning.kt:261`）。请求 64px 再放大、半径同比缩小。
- [ ] Android：SAF 镜像同步跑在 `Dispatchers.Default`（`Session.kt:39/436`），改 IO。
- [ ] Android：无障碍，格子与 28 处 `AsyncImage` 无 `contentDescription`（`Wall.kt:548-560`）。
- [ ] 核心：每张照片发 7 次事件（`engine.rs:713-730`；Android `lib.rs:100-104` 每次 JSON + JNI）。`scan-stage` 只在缩略图就绪发一次，`scan-progress` 节流，`scan-photo` 攒批。Mac 同样受益（`lib.rs:27-29` 每次 serde + eval）。
- [ ] 核心：缓存损坏当空缓存、下次保存覆盖（`cache.rs:210-217`）；`save` 错误全吞。改 `quarantine_name`。
- [ ] 核心：`scene::classify` 的 `partial_cmp().unwrap()`（`scene.rs:27`），缓存一条 NaN 向量就每次打开都 panic。`total_cmp` + 读回时过滤。
- [ ] 核心：`forget_folders` 的 `&name[..16]` 字节切片（`engine.rs:1886`）非 ASCII 文件名 panic。
- [ ] 核心：`fast_resize` 先 `to_rgb8()` 整张拷贝（`analyze.rs:404`）；缩略图走 `image::thumbnail` + 非 SIMD JPEG 编码（`analyze.rs:430-434`）；质量阶段 `blur(0.8)` + 逐像素 `get_pixel` 拉普拉斯（`analyze.rs:494-515`）。NPU 接管 CLIP 后这些 CPU 固定开销占比上来了。
- [ ] 核心：Ultra 档 SigLIP 只有一个 `Mutex<Session>`（`scorer.rs:90-115`），没跟 CLIP 一起改 Pool。
- [ ] 核心：`probe_folder` 在锁内对每个文件 `stat`，`scan_project` 同一文件再 `stat` 两次（`engine.rs:511-576`）。
- [ ] 核心：`ClipScorer::load` 每次 `scan_project` / 加文件夹 / 搜索索引都重新加载（`engine.rs:661/1676/1753/2082`）。引擎缓存一份 `Arc`，空闲后释放。
- [ ] Mac：`decide_photos` 每次整表来回（`Culling.tsx:375-379` ↔ `lib.rs:122-125`），万张项目每点一次几 MB JSON。
- [ ] Mac：`scan_project` 结束时把事件已送过的照片再整包返回一遍（`engine.rs:643-646` vs `lib.rs:105-109`）。
- [ ] Mac：分析中 FilterPanel 的 memo 被字面量打穿（`Culling.tsx:874-877`）。
- [ ] Mac：窗口状态不记忆（`tauri.conf.json:14-26`，无 window-state 插件）；不能拖文件夹进来建项目。
- [ ] Mac：离开再回项目一切归零（`Culling.tsx:263-269`）；Android 同样（`CullState` 无 `rememberSaveable`，`Culling.kt:124-170`）。
- [ ] Mac：撤销没有重做，旋转 / 废纸篓不可撤销；菜单 Undo/Redo 只对文本框有效（`lib.rs:504-512`）。
- [ ] Mac：没有 ErrorBoundary，错误条不能关（`Culling.tsx:881-884`）。
- [ ] Mac：每次标记整份 `projects.json` 全量写、无 debounce（`projects.ts:150`）。

## 安装包

QNN 六代 HTP Skel 库各 9–17 MB、`libQnnHtpPrepare.so` 84 MB。作者说两三百兆以内可接受，暂不动。若以后要减：V68（骁龙 888）和 V69（8 Gen 1）两份共 20 MB 可按最低机型取舍；`Prepare` 只在第一次编译 NPU 图时用，无法拆走。

## 核实过没问题的

取消路径、并发写缓存的锁、`huge_photo_permit`、facepipe 索引边界；Android 的硬编码文案（0 处）、暗色模式、返回键、空项目 / NAS 离线 / 权限永久拒绝分支、广播与网络回调的生命周期；Mac 的暗色、空状态、墙虚拟化、胶片条窗口化。
