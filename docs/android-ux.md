# Android 端的移动端 UX 方案

2026-10-21，作者反馈"平平无奇、跟 Mac 差得远、tab bar 怪、授权界面丑、字体和组件偏大"之后重做。原则：**功能和 Mac 一样全，布局按手机的习惯重排**——Mac 是一块大屏上同时摆开几块面板，手机是一次一屏、层层推进、拇指够得到。视觉语言（颜色、琥珀只给"保留"、Geist、动效节奏）照 DESIGN.md 不变。

## 1. 问题清单（审视当时的每一屏）

| 屏 | 问题 |
|---|---|
| 全局 | 字号是桌面端放大来的（标题 24、正文 15、按钮 14），中文回落到系统黑体后同字号看起来更大；按钮 42dp 高、带灰底描边，像网页按钮；页面左右 16dp 里再套 16dp 的卡片内边距，内容被挤窄。 |
| 标签栏 | 墨色实心胶囊当选中态太重，不像 iOS；尺寸偏大。 |
| 首页 | 桌面端的页头搬过来：大标题 + 一句说明 + "项目 / 回收站"分段 + "风格"按钮 + 搜索框，第一屏一半是控件；每张卡封面上常驻一个删除按钮（容易误点）；"新建项目"是一张虚线卡，占一整格。 |
| 新建项目 / 授权 | 授权是在底部弹层里一段灰字加一个黑按钮，没有说明为什么要、给了以后会怎样；"部分照片""被永久拒绝"两种情况也只是一行字。 |
| 设置 | 七个分区从上到下一页长滚动，顶上一排分区胶囊跳转；每行都带按钮，满屏按钮。 |
| 项目页 | 顶栏塞了"重新评估""整理"两个带框按钮加两个图标；底栏只有"浏览方式"和"撤销"。 |

## 2. 信息架构

```
标签栏（悬浮液态玻璃，只有两个页签——作者要求）
├─ 照片
│   ├─ 首页：大标题"项目"，右上 ＋（新建）与 ⋯（回收站、风格）
│   │   ├─ 搜索框（搜索模型在时）→ 全局搜索结果
│   │   ├─ 项目卡片（两列；长按：重命名 / 移到回收站）
│   │   ├─ 回收站（推进页）
│   │   └─ 风格（推进页）
│   └─ 项目（推进页，标签栏让位）
│       ├─ 顶栏：‹ 项目 · 名字 · 搜索 · ⋯（项目设置、重新评估、风格）
│       ├─ 状态条：全部 / 保留 / 待复查 / 淘汰 / 人物与场景
│       ├─ 照片墙 · 单张 · 对比 · 场景页
│       ├─ 底部玻璃条：浏览方式 · 整理 · 撤销
│       └─ 大图（全屏，上拉检查器）
└─ 设置：分级列表（像 iOS 设置）
    ├─ 通用（语言、外观）
    ├─ 分析（自动选择的模型、上次用了什么）
    ├─ 个性化（学习喜好、从文件夹学、风格、重置）
    ├─ 模型与存储（每个模型包、缓存、隐私）
    ├─ 备份（导出 / 导入、云备份、备份方式）
    ├─ NAS
    └─ 关于
```

新建项目是一个底部弹层：先说"项目从哪里来"（手机相册 / 一个文件夹 / 每台 NAS），选相册时没有权限就在弹层里换成**授权说明页**，而不是直接弹系统框。

## 3. 尺寸与字号（dp / sp）

| 用途 | 规格 |
|---|---|
| 大标题（首页、设置根页） | 28sp 粗体，往上滚时收进 17sp 的顶栏标题 |
| 页内标题（推进页顶栏） | 16sp 半粗 |
| 分组标题 | 12sp，灰，不加字距、不全大写（中文没有大小写） |
| 列表行标题 / 正文 | 15sp / 14sp；说明 12.5sp |
| 数字、计数 | Geist Mono 12sp |
| 列表行高 | 最少 52dp；左侧 28dp 圆角方块图标 |
| 主按钮 | 46dp 高、整行宽、圆角 14；次按钮是文字按钮，不加框 |
| 小按钮（行内） | 30dp 高，圆角胶囊，浅灰底，不描边 |
| 顶栏 | 48dp；图标按钮 40dp 触控区、20dp 图标 |
| 标签栏 | 胶囊 60dp 高，每个页签 74dp 宽；图标 22dp 在上、文字 10sp 在下 |
| 页面边距 | 16dp；分组卡片圆角 14，内边距 16 |

## 4. 关键界面

- **标签栏**：选中态从墨色实心胶囊改成一块更亮的玻璃（浅色是半透明白、深色是半透明灰），图标和字变成墨色，没选中的是灰色——iOS 26 的做法。拖动时这块玻璃鼓起、跟着手指。
- **首页**：去掉说明句、分段控件和"风格"按钮，收进右上的 ⋯；新建用右上的 ＋；卡片封面不再常驻删除按钮，长按出菜单。回收站做成单独一页。
- **授权说明**：一叠照片的插图、标题"让惊鸿看到你的照片"、三条说明（只在这台手机上分析 · 原图不会被改动 · 可以只给部分照片）、整行的"继续"，下面一个文字按钮"改为选一个文件夹"。部分照片和被永久拒绝各有自己的一句话和按钮（选更多 / 去系统设置）。
- **设置**：根页是分组列表，每行左边一个小图标、右边是当前值和 ›；点进去是那一组的内容。行内的操作按钮都用小号文字胶囊。
- **项目页**：顶栏只有返回、名字、搜索、⋯；"整理"挪到底部玻璃条中间（最常做的收尾动作），"重新评估"在偏好变了时以一粒玻璃提示出现在底部条上方，⋯ 里也有。

## 5. 2026-10-22 的第二轮（作者看过第一轮之后）

- **浅色主题下看不出玻璃**：照 iOS 浅色界面的做法——页面底不再是纯白，而是 iOS 分组页那种浅灰（#F2F2F7），卡片、对话框和弹层是白的；玻璃本身比底亮一点、边上一圈镜面高光、下面一道大而柔的投影、内侧一圈淡暗边；折射幅度调大（lensHeight 24 / lensAmount 56）并带色散。深色不变。
- **玻璃覆盖到的地方**：标签栏、选片底栏、大图上下两条、提示卡、下载胶囊之外，现在**所有菜单**（首页 ⋯、项目 ⋯、卡片长按、风格 ⋯、大图的实况菜单、设置里的下拉选择）都是玻璃。Material 的 DropdownMenu 是另一个窗口、拿不到背后的内容画不出折射，所以菜单画在 AppShell 根部的覆盖层里（`OverlayState` / `LocalOverlay`），从锚点那一角长出来。
- **选片底栏**：没选照片时只有"浏览方式"；选中一张就变成它的快速操作——保留（选中时琥珀色）、淘汰、放大查看，再加浏览方式。格子上不再放小坞。"整理"不是常用操作，和"重新评估""项目设置""风格""重命名"一起在顶栏 ⋯ 里；"撤销"去掉了（作者：没有用）。
- **项目设置**改成从底部推上来的整页：左上 ✕、中间标题、右上"完成"（之前的对话框没有关闭按钮）。
- **关于**：应用图标、名字、一句话、一段介绍，然后"了解更多"——官网、源代码（GitHub，AGPL-3.0）、隐私政策、使用条款、反馈问题、第三方模型与许可，最后版本。Mac 端的设置 → 关于也加了同样的内容（链接经 tauri-plugin-opener 在系统浏览器打开）。链接的地址 Android 写在 `SettingsScreen.kt`、桌面端在 `src/links.ts`，和 `apps/web/src/content.ts` 的 SITE 一致，换域名三处一起改。

- **第三轮**（2026-10-22，作者看过第二轮后）：选片底栏选中后点保留会闪——`AnimatedContent` 把判定也当键，改成只在"有没有选中"变化时换内容，判定变化只平滑换颜色；"缩略网格"简称"网格"。查看器底栏加"旋转"（顺时针 90°，Mac 端同步加了按钮与 ⌘] / ⌘[）。关于页去掉"第三方模型与许可"和版本下的说明；隐私政策、使用条款在应用内半屏浏览器（Custom Tabs 局部高度）里看。备份恢复前显示这份备份是哪台设备、什么时候做的。

- **起始屏**（2026-10-22）：作者觉得"一进来就是照片，没有项目时怪怪的"。结论是不加单独的首页也不做滑动引导页，把空状态做成第一步：和授权说明页同一套插图，一句价值（brand.tagline），三条带图标的事实，整行主按钮"从相册开始"（跳过"在哪里"那一层直接进相册；没权限先到授权说明页），下面"选一个文件夹 · 连接 NAS"两个文字入口，再下面"用示例照片先试试"（内置 10 张，不授权也能先看效果），最后隐私一句。建好第一个项目直接进项目页；只有一个项目时首页也显示通栏大卡，不显示"全部项目"。

- **准备页**（2026-10-22，作者："分析的那个界面也很丑"）：灯箱里乱叠的相片、孤零零的名字输入框、偏好的大段说明、底部三行话，全换掉。封面拼图（左一大右两小，和首页大卡一样）上压着张数、大小、预计时间；下面 iOS 分组列表：项目名称（行内直接改）、文件夹（图标行 + "添加文件夹…"行）、偏好（每行一句短说明，长解释在"?"里）、备注；底部一句话加"开始分析"。项目设置页改成同一套。

## 6. 性能（2026-10-22，模拟器 GoEnhance_API_36，4 核、arm64、发布包）

用一个 297 张照片的项目量：冷启动（`am start -W` 的 TotalTime）、照片墙来回甩动 6 次的掉帧、点选 5 次。模拟器没有真 GPU，渲染线程上的数字比真机差得多，**只用来比较改动前后**；真机数据等作者上手机测。

| | 冷启动 | 滚动：帧时间中位 / 掉帧率 | 点选：90 百分位 |
|---|---|---|---|
| 改之前（玻璃开） | 15–22 s | 550 ms / 100% | 1700 ms |
| 稳定性 + 事件合并 + 引擎后台建（玻璃开） | 3–26 s | 150 ms / 95% | 1050 ms |
| 同上，玻璃关 | 0.3–0.4 s | 150 ms / 85% | 250 ms |
| 再去掉格子阴影、懒算矩形、玻璃关时不录全屏层 | 0.3–0.4 s | **26 ms / 39%** | 800 ms（抖动大） |

用 simpleperf 看冷启动：渲染线程的时间几乎全在模拟器的 GPU 管道（`read` / `write`）里；`Dispatchers.Default` 上是 Coil 解码缩略图（libjpeg）和 JSON；主线程是类加载和字体初始化，占比不大。所以：

- **液态玻璃**在模拟器上是冷启动和滚动的大头（AGSL 折射、模糊和内容层的全屏录制）。真机（Adreno / Mali）上这套库是按 60 fps 设计的，不能用模拟器下结论；但为稳妥加了设置 → 通用 → "液态玻璃"开关，**模拟器上一律关**（开关对真机才有效），真机默认开。关掉时玻璃件退成普通磨砂片，而且不再把整页内容每帧录进一层（这层本身就是一次全屏拷贝，是滚动掉帧的主因）。
- 做了的：`compose_stability.conf` 把 core 的数据类声明稳定（格子参数没变就跳过重组）；交给格子的回调不随重组换新；筛选结果的列表身份稳定（点选不再重排整面墙）；分析事件 32 ms 合并一次、只刷新横幅那一行；引擎在后台线程建（首帧不等它）；保留格子的琥珀光晕改成画两圈圆角矩形，不用 shadow；格子的位置只记坐标对象、打开大图时再算。
- 没做、留给真机验证后再说的：Baseline Profile（主线程在冷启动时解释执行 Kotlin，有 Profile 能少 20–30%，但要加 macrobenchmark 模块在设备上生成）；缩略图改小一档（现在 640 px，网格格子只要 ~250 px）。
