# 桌面端代码审查（2026-10-20）

只读审查，基于提交 `609102d`，行号以当时的工作区为准。范围：`src-tauri/src/*.rs` 全部、`src/` 全部模块与组件、Swift 边车、配置与 CI。未运行测试或构建，性能判断来自代码路径推导，未实测。

总体：分组用完全连接避免链式粘连、决策层有真实单测、缓存分批落盘、模型校验 SHA-256、CSP 锁死前端网络、设计规则（不用黑白表示淘汰、琥珀只用于保留、循环动效只在分析中出现）在 CSS 里都兑现了。问题集中在：**分析不能取消、用户取舍存在 WebView localStorage 可能静默丢失、若干重活跑在主线程、闭眼判断在两种量表间混用、几乎所有人脸能力都绑在 Apple Vision 上**。

## 最值得先做的 5 件

1. **扫描可取消 + `last_photos` 加任务校验**（#1、#9）：同时解决 CPU 浪费、切项目后决策表错乱、探测被饿死。
2. **项目与取舍从 localStorage 搬到后端原子文件**（#2）：唯一可能让用户几小时筛选静默消失的路径。
3. **同步命令改异步，修 `pool()` 全量克隆**（#5）：按 P/X 卡顿是用户每分钟都会碰到的。
4. **闭眼量表混用 + reasons 带分项差异**（#3、#14）：直接决定"最好的一张"选得对不对、用户能不能理解为什么。
5. **跨平台人脸检测器**（#26）：Windows 路线上最大的一块，也给 Mac 上 Vision 崩溃兜底。

紧随其后：模型下载续传 + 镜像/手动导入（#19）；HEIC 探测的 5 次子进程（#6）。

## 隐私承诺核查：兑现

网络只有 `modelpacks.rs` 一处 `ureq`；CSP 封死前端 fetch；无 updater、无埋点、无崩溃上报。本地落盘：`analysis-cache.json`（路径、分数、向量）、`styles.json`（标签、参考文件夹）、`scene-sentences.json`（**照片内容的文字描述**）、`thumbs/`（640 px 缩略图 + 1024 px 分析副本，永不清理）。建议在隐私说明里列出分析副本和场景描述文本。`assetProtocol` scope 为 `$HOME/**`，当前无远程内容注入面，将来若在 WebView 里加载远程页面会成为风险。

## 可疑但不确定

- JPEG（`image` + 双线性）与 HEIC/RAW（ImageIO 缩略图解码）走不同解码路径，清晰度分数可能系统性不同，需同一张图两种格式实测。
- Tauri 2 同步命令是否一定在主线程（#5 的严重度依赖此）。
- `analyze.rs:351-355` 用 `DefaultHasher` 生成缓存文件名，标准库不保证跨版本稳定；建议换固定算法。
- `ort` 的 `coreml` feature 在 Windows 上能否编译未验证。
- `analyze.rs:177` `face_min` 取最小值，合影里远处路人会拉低整张的人脸分。
- `florence.rs:116-139` 解码不带 KV cache，几百个场景的项目后台耗时未实测。
