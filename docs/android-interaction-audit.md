# 安卓端交互走查（2026-11-05）

在模拟器 fg_test_api36 上用 main（1bfd999）的包，中文界面，逐屏点了一遍：首页、新建项目、照片墙（四种浏览方式）、筛选、大图、检查器、整理、项目设置、搜索、设置的七个分区。只记问题，不含修改。

没走到的：分析过程页、照片授权页、场景视图、人物筛选、添加 NAS 的流程、真机上的液态玻璃。

根子上的问题只有一个：**同一件事有好几套控件、好几个入口，各自是不同时候加的，没有定过"这件事只在哪里做"。** 下面按这个思路分三组。

## 一、判定（保留 / 待复查 / 淘汰 / 星级）——最该先收拾

**这一组已在 2026-11-05 改完**（模拟器上逐项验证过）：

- 1：浏览方式按钮固定在页签右边；底栏只在多选和对比页出现，每个位置只有一种意思。
- 2：顶栏有撤销按钮（有可撤销的才出现）；大图里判完或打完星，小图条上方浮出"撤销"四秒。
- 3：单张布局只剩照片下面那一套，星级也在那一行。
- 4：对比页的卡片按钮管单张，底栏改叫"只留第 N 张"（留下这张、同屏其余淘汰、跳下一组），这是作者 2026-10-23 要的快捷取舍，保留。
- 5：检查器只放分数、理由和数据，不再有判定和星级。
- 6：墙上不再有那条会把"保留"变成"撤销"的底栏。
- 7：淘汰的照片右上角有深色圆里的 ×（瀑布、网格、单张、小图条都有），照片仍是彩色。
- 8：能打星的地方是大图和单张；多选和对比不打星。
- 9：我淘汰的那张不再挂"推荐"。
- 10：长按进多选，可以一次保留 / 待复查 / 淘汰一批，算一步撤销。

## 建议的顺序

1. 第一组的 1、2、7：防误触、能撤销、淘汰看得见。这三条直接影响会不会判错。
2. 第一组的 3、4、5、6：每种浏览方式里判定只留一套。
3. 第二组的 11、15、17：把"整理"提出来，去掉重复的筛选和信息卡。
4. 其余按屏收拾。

## 待办：NAS 密码的钥匙跟着系统备份走（2026-11-05 发现，作者说先不改）

`packages/core/src/secrets.rs` 把 NAS 密码、备份密钥用 AES-256-GCM 加密存在 `secrets.json`，解密用的 `secrets.key` 就在同一个目录。
安卓的 AndroidManifest 没有写 `allowBackup`，默认是开的：系统备份到谷歌云、换机迁移时，钥匙和密文会一起带走。
改法：安卓端把 `secrets.key` 换成存进 Android Keystore 的密钥（不随备份走），或者至少用备份规则把 `secrets.key` 排除掉。Mac 端不受影响。
